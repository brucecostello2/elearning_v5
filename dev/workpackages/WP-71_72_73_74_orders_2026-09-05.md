## WP-71 — MOTION ASSET WRITE: S1 plus its JSON binding (N5)

**Defect.** `ivgs-workers/services/motion_graphics.py:598` inserts into `assets` naming `storage_path`, `metadata` and `status`; the table has `seaweedfs_path` and `generation_metadata` (`ivgs-api/migrations/versions/0001_initial_core.py:157`; `0028_wp45_provenance_scene_fields.py:51`) and no `status`. The service sets `asset_type="animation"` (`:270`, `:420`), which the DB enum lacks (`0001_initial_core.py:40`; members extended only by `0025_add_reference_clip_asset_type.py:23`). Its `metadata` parameter is bound as `str(metadata)` (`:614`) — Python text into a JSONB column; correcting the column names alone exposes that next error. Every motion-graphics asset registration through this path fails; the enclosing stage's reporting of that failure is not established.

**Fix (service only; the calling stage body is frozen).** Column names → `seaweedfs_path`, `generation_metadata`; drop `status` from the INSERT; bind `generation_metadata` as JSON (`json.dumps` with an explicit `::jsonb` cast, or the driver's JSON adapter — one of the two, stated); `asset_type` → the existing enum member that the reader side expects for rendered motion clips (`video` unless a reader of `animation` is found — search first and state the result). Adding `animation` to the enum is a migration and is **not** done here; if the reader analysis shows it is needed, report it as a decision.

**Tests.** (1) A schema-shape test that parses the migration chain's `assets` column list and asserts the INSERT's column list is a subset of it, and that the `asset_type` literal is a member of the enum at head 0054 — this fails today and needs no database. (2) A round-trip test against a PostgreSQL test database (the repository's testcontainers pattern or the compose Postgres): insert through the service function, read back, assert `generation_metadata` equals the original dictionary. If no database is reachable in the executor's environment, (1) is the failing test and (2) is recorded as an environment note with the exact command the operator can run on node-01.

**Files.** `ivgs-workers/services/motion_graphics.py` and its tests only.

**Exit (operator).** Parent commit: test (1) fails; fix commit: passes. On node-01 after deploy: run test (2) against the compose Postgres; a motion asset row exists with a JSON `generation_metadata`.

## WP-72 — DELETION RESERVATION LEDGER (N6; corrected premise)

**Defect.** WP-69 listed `sched:reservation:*` as keys the scheduler never writes. That premise is **false**: the scheduler writes the reservation hash, the durable ledger, the index and the job map (`ivgs-scheduler/scheduler.py:410, :426, :431, :445, :453`). The real defect is narrower: the deletion service's reservation enumerator (`ivgs-api/app/services/project_deletion.py:553`) checks only the expiring hash and skips an index member when that hash is absent, so after the hash and job map expire while the durable ledger and index remain, it returns no reservations for the project. The release path already recovers from the ledger (`ivgs-scheduler/admission_control.py:375`). Reproduced by the Codex reassessment against synthetic Redis states; a deletion falsely declaring success on node-01 is unverified.

**Fix.** Enumerate from the index and, for members whose hash is absent, consult the durable ledger; release or cancel each found reservation through the scheduler's existing release contract; proceed with deletion only after every found reservation is released or confirmed absent; idempotent on retry. Do not rename keys; do not change the scheduler's write side.

**Tests.** Against a fake or test Redis: (a) live reservation (hash present) → found and released; (b) expired hash, ledger and index present → found and released — this is the failing case today; (c) nothing present → empty, deletion proceeds; (d) the same call twice → second call is a no-op. Assert the deletion service refuses to declare success while a found reservation remains unreleased.

**Files.** `ivgs-api/app/services/project_deletion.py` and its tests. If the scheduler's release contract needs a client method that does not exist, stop and report it as a decision rather than adding to the scheduler.

**Exit (operator).** Parent commit: test (b) fails; fix commit: passes. No live deletion is run as part of this package.
